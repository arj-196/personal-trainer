# Retire the GHCR push pipeline; caretaker deploys trainer-api

The GitHub Actions deploy pipeline (`deploy-trainer.yml`: pytest → build amd64 image → push to GHCR → SSH to the VPS → migrate → restart) is retired, along with `deploy/trainer/docker-compose.yml`. ADR-0001's GHCR/VPS deployment story no longer applies. Production trainer-api now runs on the Mac mini and is deployed by **caretaker** (`github.com/arj-196/caretaker`), a pull-based poller on the mini that watches this repo's `main`, resets its local checkout, rebuilds the image from source (arm64, no registry), runs `personal-trainer db setup --prod` on the new image while the old container still serves, then swaps containers. The compose service definition (with the `/health` healthcheck carried over from the old deploy compose) lives in caretaker's central compose, not here — this repo carries no deploy configuration at all; even the migration step is a hook in caretaker's config.

Consequences: every push to `main` deploys, ungated — the test suite still runs in CI (`trainer-ci.yml`) but is advisory; a broken build leaves the old container serving and blocks that SHA until the next push (caretaker notifies via Telegram). Runtime secrets move from the VPS `.env` to `central/env/.personal-trainer.env` on the mini, and per ADR-0002 must include `OPENROUTER_API_KEY` (plus optional `LLM_BASE_URL` / `TRAINER_MODEL` / `TRAINER_CHAT_MODEL` overrides) — not the retired `OPENAI_*` set. The GitHub deploy secrets (`VPS_*`, `GHCR_*`) and the `production` environment are dead and can be deleted from the repo settings.
